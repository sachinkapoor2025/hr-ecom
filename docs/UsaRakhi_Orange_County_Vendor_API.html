3. How to fulfill vendor requirements (end-to-end)

  1. Import orders — poll GET /vendors/orange-county/orders (default last 15 days). Use pagination if more than 50 orders.
  2. Match SKUs — use items[].sku / productCode (e.g. TFUSRH2026-16).
  3. Ship — use recipient address fields + gift message; store orderNumber (OC10001…) as your external reference.
  4. When shipped — call AWB API with orderNumber, courierName, awb.
  5. When status changes — call tracking API with orderNumber and currentShipmentStatus.
  6. Avoid duplicates — keep imported orderNumbers locally; use updatedSince for incremental sync.
Do not use the public website API host — only the Base URL above (Vendor API).

Accepted status examples (case-insensitive): processing, packed, shipped, in_transit, dispatched, out_for_delivery, delivered, complete.

5. List query parameters

daysDefault 15 — only orders created in the last N days (max 90)
limitPage size — default 50, max 200
cursorOpaque token from previous nextCursor (next page)
sinceISO timestamp — createdAt lower bound override
updatedSinceISO — only orders with updatedAt ≥ this time (incremental sync)
statusExact status filter, e.g. paid, processing, shipped

Without status, unpaid / cancelled / refunded orders are hidden.

6. Response fields (order)

  • orderId / orderNumber — human-readable OC10001, OC10002, …
  • internalOrderId — internal UUID (support only; prefer orderNumber)
  • orderDate / createdAt / updatedAt / status
  • senderName, giftMessage
  • recipientName, recipientAddressLine1, recipientAddressLine2, city, state, country, zipCode, recipientPhoneNumber
  • orderValue — total fulfill / purchase amount (USD vendor cost × qty). Not retail.
  • deliveryDate, trackingNumber, carrier, shippingServiceName

Item fields

  • sku / productCode — your product SKU
  • productName, quantity
  • price — vendor unit cost (not website selling price)
  • productImageUrl, weight, weightUnit (oz)

Not included: retail selling price, discounts, or other vendors’ products.
